# fpbench 第一人称 K 帧工作台：说明文档

版本：2026-11-18（ysm/pelica-fix 提交 c85538f 及之后）

## 1. 这是什么

fpbench 用来离线调整 YSM 模型在 TACZ 第一人称持枪时的手部动作，不需要启动 Minecraft。它能做四件事：

| 功能 | 命令 | 速度（本服务器，8 核，缓存已建好） |
|---|---|---|
| 渲染第一人称画面和手部特写 | `render` | 约 0.13 秒/帧（960×540） |
| 把一段动画按时间轴拼成一张图 | `sheet` | 12 帧约 2.6 秒，带指标约 12 秒 |
| 测量手和枪的贴合情况（穿模深度、间隙、腕部角度等） | `metrics` | 约 0.8 秒/帧 |
| 握把 IK：自动弯曲手指，贴住枪面但不穿进去 | `ik` | 1～4 秒 |
| 和游戏内截图对比误差 | `compare` | 7～20 秒 |

改一次关键帧，几秒内就能看到画面和数值，不用每次进游戏。

**准确度**：和测试服的游戏截图逐像素对比过（960×540）：

| 枪 / 状态 | 轮廓重合度 IoU | 手在握把上的偏差（左 / 右，像素） |
|---|---|---|
| AK47 待机 | 0.9999 | 0.01 / 0.01 |
| M4A1 待机（拟合握把） | 0.9968 | 0.01 / 截图里看不到右手 |
| Glock17 待机 | 0.9997 | 0.01 / 0.00 |
| AK47 战术换弹 1.20 秒 | 0.986 | 0.23 / 0.54 |
| M4A1 战术换弹 2.01 秒 | 0.992 | 0.26 / - |
| Glock17 战术换弹 0.80 秒 | 0.998 | 0.25 / 0.03 |

待机画面和游戏逐像素一致。换弹时的残差来自截图时刻的估算精度（按 10 毫秒步进），这时手 10 毫秒内最多会移动 15 像素。

## 2. 包里有什么

```
fpbench/
  fpbench            启动脚本（bash）
  fpbench.py         命令行入口
  fpb/               Python 实现
    ysm_arm.py       调用 YSM 导入器取第一人称手臂模型，骨骼/蒙皮/Molang 求值
    tacz_gun.py      读取 TACZ 枪包：模型、贴图、显示参数、动画
    scene.py         枪和手臂在第一人称里的摆放（复刻 TACZ 1.2.0 + YSM 的变换链）
    raster.py/.c     软件光栅化（C 内循环首次使用时自动编译，没有编译器时退回纯 numpy）
    render.py        出图：第一人称画面、手部特写、时间轴拼图
    metrics.py       贴合指标
    ik.py            握把 IK
    compare.py       和游戏截图对比
    molang.py        Molang 表达式求值
  java/.../FpDump.java  用 YSM 自己的导入器离线转换模型、导出手臂数据
  README.md          英文说明（含完整变换链和源码行号）
  说明文档.md        本文档
示例/                示例输出（见第 9 节）
```

包里**不含**：TACZ jar、Minecraft 库文件、模型文件。这些按第 3 节准备。

## 3. 运行环境

在这台服务器上（`~/ysm/pelica-fix/tools/fpbench`）所有依赖都已就绪，可以直接用，跳到第 4 节。

在别的机器上需要：

| 依赖 | 说明 |
|---|---|
| Linux 或 WSL | 类路径用 `:` 分隔，YSM 原生库用的是 Linux 版 `libysm.so`；Windows 请用 WSL |
| Python 3.10+，numpy，Pillow | `pip install numpy pillow` |
| C 编译器（可选） | `cc`/`gcc`/`clang` 任一，用来编译光栅化内循环；没有也能跑，只是慢一些 |
| JDK 17（`java` 和 `javac`） | 只在第一次转换某个模型时用到 |
| 我们的 YSM jar | `ysm-3.0-dev-forge+mc1.20.1-pelica-motion.jar`（v10 完整交付包里的 `mods/` 目录） |
| YSM 的 Linux 原生库 | 从上面的 jar 里解压：`unzip -j ysm-…-pelica-motion.jar META-INF/native/libysm.so -d ~/fpb-native` |
| Minecraft 1.20.1 + Forge 的 `libraries` 目录 | 启动器的 `.minecraft/libraries` 整个复制过来即可（导入器需要里面的 protobuf、guava 等库） |
| TACZ 1.2.0-hotfix jar | `tacz-forge-1.20.1-1.2.0-hotfix.jar`，自行下载。默认枪包和默认动画都从它读取 |

用环境变量告诉 fpbench 这些文件在哪里：

| 环境变量 | 含义 | 服务器上的默认值 |
|---|---|---|
| `FPBENCH_YSM_JAR` | 用哪个 YSM jar 的导入器转换模型（也可以用 `--ysm-jar`） | `~/mc/client/mods/ysm-3.0-dev-forge+mc1.20.1-pelica-motion.jar` |
| `YSM_NATIVE_PATH` | YSM 的 Linux 原生库 | `~/mc/client/home/.ysm/unstable/libysm-core-3.0-dev-forge+mc1.20.1.so` |
| `FPBENCH_MC_LIBS` | Minecraft/Forge 的 `libraries` 目录 | `~/mc/client/libraries` |
| `FPBENCH_TACZ_JAR` | TACZ jar | `~/ysm/bfm-port/libs/tacz-forge-1.20.1-1.2.0-hotfix.jar` |
| `FPBENCH_CACHE` | 缓存目录（转换后的模型、编译好的 FpDump 和光栅化库） | `~/.cache/fpbench` |

另一台机器上的示例：

```bash
export FPBENCH_YSM_JAR=~/fpb/ysm-3.0-dev-forge+mc1.20.1-pelica-motion.jar
export YSM_NATIVE_PATH=~/fpb-native/libysm.so
export FPBENCH_MC_LIBS=~/fpb/libraries
export FPBENCH_TACZ_JAR=~/fpb/tacz-forge-1.20.1-1.2.0-hotfix.jar
F=~/fpb/fpbench/fpbench
$F guns          # 能列出 70 把枪就说明 TACZ jar 找到了
```

这套"v10 jar + 从 jar 里解压出的 libysm.so + 换了位置的 TACZ jar"的组合在服务器上实测过，可以正常转换佩丽卡并出图。

## 4. 快速上手

```bash
F=~/ysm/pelica-fix/tools/fpbench/fpbench
$F guns                                   # 列出所有枪的 id
$F clips --gun tacz:ak47                  # 列出这把枪的动画片段和时长
$F render --gun tacz:ak47 --clip reload --t 1.2 --out /tmp/a.png --closeups --highlight
```

第一次用某个模型时，会先用 YSM 导入器转换一遍，约 20～25 秒，结果会缓存；模型、jar 或 FpDump 改了才会重新转换。

`--model` 默认是 `~/ysm/pelica-fix/pelica_springs/pelica.vrm`，用别的模型时传 `--model 路径`（`.vrm`、`.zip` 或 `.ysm` 文件夹都可以）。

## 5. 命令详解

### 5.1 通用参数（所有出图、测量命令都支持）

| 参数 | 含义 |
|---|---|
| `--model` | 模型文件 |
| `--gun ns:id` | 枪的 id，例如 `tacz:ak47`、`tacz:m4a1`、`tacz:glock_17` |
| `--pack 路径` | 额外的枪包（zip 或文件夹），可写多次，优先于 TACZ jar 里的默认枪包 |
| `--clip` | 动画片段：`idle`（默认）、`draw`、`reload`（等于 `reload_tactical`）、`reload_empty`、`inspect`、`shoot`，或 `clips` 列出的任意片段名 |
| `--t` | 片段内的时间（秒） |
| `--idle-t` | 循环待机晃动的相位（秒）；`--no-sway` 去掉晃动 |
| `--no-bob` | 模拟"视角摇晃"关闭。TACZ 只在视角摇晃开启时把枪的镜头动画作用到手上；游戏默认开启 |
| `--fov` | 手部视野，默认用枪的 `model_fov`（没写时 70） |
| `--size` | 画面尺寸，默认 `960x540` |
| `--empty` | 弹匣为空（隐藏子弹部件） |
| `--pose 文件` | 应用一个补丁 JSON（见第 6 节），可写多次；`ik` 的输出文件也能直接用 |
| `--ysm-jar` | 用哪个 YSM jar 转换模型 |

### 5.2 `render`：出一张第一人称画面

```bash
$F render --gun tacz:m4a1 --clip reload --t 0.8 --out /tmp/r.png --closeups --highlight
```

- 输出游戏视角的 PNG。
- `--closeups`：另外输出 `<out>_hands.png`，是每只手在握把附近的正视和侧视特写（正交投影），标注每根手指的穿模深度和间隙。
- `--highlight`：把插进枪里的手部顶点涂成红色。

### 5.3 `sheet`：整段动画拼成一张图

```bash
$F sheet --gun tacz:ak47 --clip reload --frames 12 --metrics --highlight --out /tmp/s.png
```

- `--frames N`：在 `[--t0, --t1]` 之间均匀取 N 帧（`--t1` 默认是片段时长）；`--times 0.2,0.5,1.0` 指定具体时间。
- `--cols`：每行几格（默认 4）；`--thumb`：每格宽度（默认 480，0 = 原尺寸）；`--crop x0,y0,x1,y1`：先裁剪再缩放。
- `--metrics`：每格标注两只手插进枪里的顶点数。

### 5.4 `metrics`：测量贴合情况

```bash
$F metrics --gun tacz:m4a1 --json /tmp/m.json            # 单帧
$F metrics --gun tacz:m4a1 --clip reload --frames 8      # 一段时间轴
```

输出示例（M4A1 待机，修正前）：

```
tacz:m4a1 idle t=0.000s fitted=True (px = 1/16 block)
 Left: Thu pen 0.19(35) gap 0.00; Ind pen 0.30(113) gap 0.00; ...
   palm pen 0.09(38) gap 0.00; grip barrel2,bone,octagon: palm-axis 1.70 px, knuckles/axis 28 deg, thumb opp 100 deg
   wrist flex 30.1 dev -29.4 twist -78.3
 Right: ...
   wrist flex -9.0 dev -39.1 twist 3.2 OUT OF RANGE {'deviation': -9.08}
 hand-hand min 10.99 px, arm-arm min 10.24 px, hand-in-gun vertices {'Left': 379, 'Right': 56}, ...
```

单位是模型像素（1/16 方块，枪模和手臂模型用的都是这个单位），在视图空间里计算。

| 指标 | 含义 |
|---|---|
| `pen 0.30(113)` | 这根手指最深插进枪里 0.30 像素，共 113 个顶点在枪里 |
| `gap` | 没插进去时，离枪表面最近的距离 |
| `Thu/Ind/Mid/Rin/Lit/palm` | 拇指、食指、中指、无名指、小指、手掌 |
| `grip …` | 自动识别的握把部件（掌心 2.5 像素内的枪部件，可用 `--grip-parts` 指定） |
| `palm-axis` | 掌心到握把主轴的距离 |
| `knuckles/axis` | 指根连线和握把轴的夹角 |
| `thumb opp` | 拇指尖和中指尖绕握把轴的夹角（越接近 180° 越像"握住"） |
| `wrist flex/dev/twist` | 手相对前臂的屈伸、偏斜、扭转。限位：屈伸 -70～80，偏斜 -30～20，扭转 ±90；超出时显示 `OUT OF RANGE` |
| `hand-hand` / `arm-arm` | 两手之间、两臂之间的最小距离 |
| `hand-in-gun vertices` | 每只手插进枪里的顶点总数，最直观的"穿模程度" |

`--json` 输出完整数据（含每根手指的 `tip_gap_px`、`nearest_part` 等），给脚本或 AI 读。注意弹匣也算枪的一部分，换弹时手拿着弹匣会被计为"在枪里"。

### 5.5 `ik`：握把 IK

```bash
$F ik --gun tacz:m4a1 --out /tmp/grip.json --render /tmp/ik.png
```

- 按导入器的手指参数化方式（每节手指绕自己的弯曲轴转一个角度）合拢手指：所有关节一起弯，某一节距离枪面小于 `--clearance`（默认 0.1 像素）时，这节和它之前的关节停下，后面的继续弯；碰到关节限位也停。
- 如果手指张开时某一节就已经在枪里，说明手本身的位置插进了枪，这一节允许保持原深度但不能更深，其余部分照常贴合。
- 某根手指原来的姿势如果比求解结果穿模更少，就保留原来的。
- 默认处理扶枪手（左手）全部五指，以及持枪手（右手）除扳机食指以外的四指；用 `--fingers LeftIndex,RightThumb` 或 `--sides Left` 限定。
- `--render` 另外输出 `_before` / `_after` 的手部特写。

输出文件内容：

| 字段 | 用途 |
|---|---|
| `animations.parallel2.bones.<手指><n>.rotation` | 数值关键帧，格式和导入器生成的第一人称手臂动画一致 |
| `fpbench.importer_layer` | 导入器原本的 Molang 旋转字符串，只把持枪分支换成求解值。拟合握把的枪是 `ctrl.tac_grip('fitted') ? 值`，其他是 `ctrl.tac_hold_gun ? 值`。可以直接替换生成的 `parallel2` 条目 |
| `fpbench.importer_tables` | `FITTED_SUPPORT_HAND` / `FITTED_GUN_HAND` 弯曲角数组，可直接粘进 `HumanoidImport` |
| `fpbench.curl` | 每根手指每节的弯曲角 |
| `metrics_before` / `metrics_after` | 求解前后的指标 |

M4A1 待机的实测效果：左手在枪里的顶点 379 → 55，右手 56 → 0。剩下的 55 个是指根和拇指根，张开手时就已经在护木里，要改握把位置才能消掉（见第 7 节）。

### 5.6 `compare`：和游戏截图对比

```bash
$F compare --gun tacz:ak47 --no-bob --shot 游戏截图.png --fit --out /tmp/overlay.png --json /tmp/c.json
```

- 截图要求：960×540（或和 `--size` 一致）、背景是天空（抬头约 45°）、HUD 开着（按 F1 隐藏 HUD 时游戏不画手）、界面缩放 2；其他 HUD 模组要自己遮掉。测试服关了视角摇晃，所以要加 `--no-bob`。
- `--fit`：先拟合截图时刻未知的片段时间和晃动相位。
- 输出叠加图：渲染轮廓红色，游戏轮廓绿色；打印枪、左臂、右臂各自的偏移和 IoU。

### 5.7 `guns` / `clips`

```bash
$F guns [--pack 枪包.zip]        # 列出枪 id
$F clips --gun tacz:m4a1         # 列出片段名和时长
```

### 5.8 `profile`：生成每把枪的手部配置

```bash
$F profile --models ~/ysm/efdata/models-patched-20261118 --only pelica,aglina,aurora --guns tacz:m4a1,tacz:ak47 --out profiles
```

按模型逐个求解握把位置、待机手指和换弹（默认 `reload_tactical`，每秒 15 帧 IK，平滑、精简关键帧），输出
`profiles/tacz/m4a1.json` 等文件（放进 `config/ysm_tacz_fp/`），并打印每个模型修正前后的穿模深度。模型 id 是模型
文件夹名，`--fallback` 指定的模型（默认 pelica）同时作为 `*` 通用配置。新模型、新枪直接重跑即可。

注意：现在测量时枪是"实心"的：由薄板拼成的空心护木（如 M4A1 的 `octagon`）按其凸包计算，以前只按方块计算会漏掉约
1 px 的指节穿模。

## 6. 补丁 JSON（`--pose`）

```json
{
  "curl":  {"LeftIndex": [40, 60, 30], "RightThumb": [20, 30, 25]},
  "bones": {"LeftHand": [10, 0, -5]},
  "gun":   {"lefthand_pos": {"position": [0, 1, 0], "rotation": [0, 0, 10]}},
  "grips": {"tacz:ak47": {"left": [5, 18, 1, 80, -60, -50], "right": [-7, 13.8, -1.3, 38, 0, 9]}}
}
```

| 字段 | 含义 |
|---|---|
| `curl` | 每根手指每节的弯曲角（度），和 `HumanoidImport` 里 `FITTED_*` 表的参数化相同 |
| `bones` | 手臂骨骼的关键帧旋转（度），沿用导入器的约定（叠加在静止姿势上，X、Y 取反），替换生成值 |
| `gun` | 枪部件的 Bedrock 关键帧值，作为最后一层（不混合）叠上去 |
| `grips` | 覆盖 TaczGrips 的拟合握把表，每只手 `[x, y, z, rx, ry, rz]`，`null` 删除该项。写在这里的枪会被当作拟合握把（`ctrl.tac_grip('fitted')` = 1） |

`ik` 的输出文件也能当补丁用：它的 `animations.parallel2.bones` 会被读成 `bones`。多个 `--pose` 按顺序合并，同一根骨骼、同一根手指或同一个枪部件以后面的文件为准（不是累加）。

## 7. 推荐工作流

```bash
F=~/ysm/pelica-fix/tools/fpbench/fpbench; G=tacz:m4a1
$F render  --gun $G --out /tmp/a.png --closeups --highlight      # 1. 看画面，红色是插进枪里的部分
$F metrics --gun $G --json /tmp/m.json                           # 2. 看数值
$F ik      --gun $G --out /tmp/grip.json --render /tmp/ik.png    # 3. 让 IK 给出手指弯曲
#   或者手写补丁：{"curl": {"LeftRing": [10, 60, 45]}, "bones": {"LeftHand": [..]}}
$F metrics --gun $G --pose /tmp/grip.json                        # 4. 套用补丁重新测量
$F sheet   --gun $G --clip reload --frames 12 --metrics --pose /tmp/grip.json --out /tmp/s.png   # 5. 检查整段动画
```

重复 3～5，直到穿模接近 0、间隙不超过 clearance。然后把弯曲角或 `FITTED_*` 表移植进 `HumanoidImport`，重新构建 YSM jar，进游戏确认一次（可以再用 `compare` 和游戏截图对比）。

经验：
- IK 报告某根手指 `inside gun when open: links [0]`，说明指根张开时就在枪里，该改的是手的位置（TaczGrips 表，或补丁里的 `grips`），不是手指。
- 腕部角度超出限位，也说明握把表需要调整。

## 8. 原理：怎么保证和游戏一致

fpbench 逐步复刻了游戏里的变换，每一步都对照 TACZ 1.2.0-hotfix 的反编译代码和 YSM 源码，行号见 `README.md` 的 "Transform chain" 一节。简述：

1. **投影**：手部用 FOV 70，TACZ 换成枪的 `model_fov`，近平面 0.05。
2. **手部晃动**：原版的视角晃动被 TACZ 抵消，站着不动时为零。
3. **镜头动画**：枪动画里 `camera` 骨骼的旋转只在"视角摇晃"开启时作用到手上（这就是 `--no-bob` 存在的原因）。
4. **枪的摆放**：`translate(0,1.5,0)`、绕 Z 转 180°、乘以待机视角的逆变换；腰射时瞄准权重为 0。
5. **Bedrock 枪模**：骨骼位置、旋转顺序、方块 UV 映射都按 TACZ 的加载代码处理。
6. **动画**：位置除以 16 并翻转 Y；旋转按 Rz·Ry·Rx 转四元数；线性或 Catmull-Rom 插值；状态机的轨道分层（基础待机、主动作、射击叠加、移动晃动）。
7. **手**：枪上的 `lefthand_pos` / `righthand_pos` 定位点 → YSM 第一人称手臂渲染；拟合握把的枪先做 TaczGrips 的缩放和掌心平移，再 `translate(±0.25, 1.8, 0)`、`scale(-1,-1,1)`。
8. **YSM 骨骼**：静止姿势加关键帧（X、Y 取反），蒙皮矩阵即姿势矩阵。第一人称手臂只由 `parallel2` 驱动；持枪时 `ctrl.tac_hold_gun` = 1，拟合握把的枪 `ctrl.tac_grip('fitted')` = 1。

## 10. 限制

- 光照、明暗、贴图过滤是近似的，只有轮廓和几何位置是准确的。
- 不画附魔光效、枪口火焰、抛壳、配件、瞄具，也不支持瞄准（只算腰射）。
- 片段开头 0.2 秒的状态机过渡、跑步和行走片段、射击后坐的时序是近似处理（`shoot` 当作独立片段）。
- 指标把枪当作所有方块的并集（含弹匣），检测的是手部顶点而不是面；比手部顶点间距还薄的枪部件可能从顶点之间穿过而测不出来。
- 只覆盖导入器生成的第一人称手臂（`HumanoidImport.arm()`），不覆盖第三人称。
- `compare` 需要天空背景和默认界面缩放 2 的 HUD 布局。
- IK 算出的手指动作还没移植进 `HumanoidImport`，也没进游戏试过。

## 11. 常见问题

- **`gun tacz:xxx not found`**：TACZ jar 没找到，检查 `FPBENCH_TACZ_JAR`；或者这把枪在别的枪包里，用 `--pack` 加上。
- **`FpDump failed`**：通常是 `FPBENCH_MC_LIBS` 不是完整的 Minecraft/Forge `libraries` 目录，或者 `YSM_NATIVE_PATH` 指向的不是 Linux 版原生库。错误信息里会附上 Java 的输出。
- **第一次很慢**：首次转换模型约 20～25 秒，首次使用会编译 C 光栅化库；之后走缓存。缓存在 `FPBENCH_CACHE`，删掉即可强制重建。
- **换了模型或 jar 没生效**：缓存按模型、jar、FpDump 的内容哈希区分，内容变了会自动重新转换；只改了文件名不会。
