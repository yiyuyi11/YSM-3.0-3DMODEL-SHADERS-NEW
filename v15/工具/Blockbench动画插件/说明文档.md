# YSM 3D Animator（Blockbench 插件）说明文档

版本 1.0.0（2026-11-18，ysm/pelica-fix 分支 animkit）

给 YSM 导入的 3D 模型（VRM 等）做动画的 Blockbench 插件：

- 第三人称（YSM 的 `main` 动画组）和第一人称（`fp_arm` 动画组）各一个标签页；
- 蒙皮网格实时跟随骨骼：摆姿势、播放、拖时间轴都会变形；
- 生成动作作为只读参考，自己的动作单独存放、导出到模型文件夹，游戏里叠加在生成动作上；
- 还能绘制模型贴图和 endfield_npr 渲染贴图，并写回 VRM。

需要配套的 YSM 模组 jar（带骨架导出器 RigExport 和动画叠加功能）：`ysm-3.0-dev-forge+mc1.20.1-animkit.jar`。

## 1. 安装

1. Blockbench 4.12 或更新（5.x 已测试）。桌面版和网页版（web.blockbench.net）都能用。
2. 文件 → 插件 → 右上角“从文件载入插件”，选择 `ysm3d_animator.js`。
3. 桌面版第一次运行导出器、读写模型文件夹时，Blockbench 会询问权限（“启动外部程序”、“访问文件”），选“总是允许”。

## 2. 导入模型

### 方式一：桌面版直接导入（用 Java）

文件 → 导入 →“YSM 3D 模型”，选模型文件夹（或其中的 .vrm/.pmx 等）。插件会运行 YSM jar 里的导出器，约 10 秒。

- 导出的是游戏从这个文件夹实际加载的模型：`ysm.json` 指定的，否则是文件夹里最大的模型文件。
- 路径在 设置 → “YSM 3D 动画”：
  - Java 路径（Java 17+；留空用系统 PATH 里的 java）；
  - YSM 模组 jar；
  - `.minecraft/libraries`。
- 第一次会自动检测 `.minecraft`：`mods`、`versions/*/mods`（HMCL/PCL 版本隔离）、`libraries`，以及官方启动器自带的 Java。也可以点“自动检测 .minecraft”。
- 导出结果缓存在 `用户目录/.ysm3d_animator/rigs/`，保存的 .bbmodel 重新打开时直接用它重建预览。

### 方式二：打开 .ysmrig.json（网页版用这个）

没有 Java 或用网页版时，先在电脑上用导出器生成 `.ysmrig.json`：

```
tools/animkit/ysmrig.bat <YSM jar> <.minecraft 文件夹> <模型文件夹> <输出.ysmrig.json>
```

然后：文件 → 导入 →“YSM 骨架文件 (.ysmrig.json)”，或者直接把文件拖进 Blockbench。

## 3. 两个标签页

导入后会打开两个标签页：

- **「<模型> 第三人称」**：完整模型和 `main` 骨架；
- **「<模型> 第一人称」**：YSM 第一人称手臂模型（`LeftArm` / `RightArm` 两棵骨骼树）。

骨骼是普通的 Blockbench 组，用 Blockbench 自己的 Bedrock 读取器建成：轴心、静止旋转与 YSM 完全一致。时间轴、曲线编辑器、IK、Molang 都能直接用。

模型的网格不是 Blockbench 元素：不会被保存进模型、不能选中，也不会挡住选择。

### 第一人称视图

视图 →“第一人称视图…”：

- **手持状态**：
  - 空手（主手）：原版只画主手手臂，在右下角；
  - 主手持地图（副手有物品）；
  - 双手持地图（副手为空），可以设视线俯仰，往下看时地图和双手会升起来；
  - TACZ 枪：选枪包 zip（或 TACZ 模组 jar，里面有默认枪包），枪按 TACZ 的位置摆放，双手放到枪的 `lefthand_pos` / `righthand_pos` 上。M4A1 的拟合握把（TaczGrips）也会生效。
- **FOV**：默认 70，Minecraft 画手时固定用 70；TACZ 枪会用枪包里的 `model_fov`。
- **显示原版手臂轮廓（参考）**：蓝色线框，是原版 Steve 手臂在同一位置的样子。

相机放在眼睛处、看向前方，和游戏一样。可以随意旋转查看，视图 →“回到第一人称相机”可以复位。

注意：原版只在**空手**和**拿地图**时画手臂，拿其他物品时游戏里看不到第一人称手臂（TACZ 等模组会自己画）。

第一人称画面用的是：

- Minecraft 1.20.1 的 `ItemInHandRenderer`、`GameRenderer`；
- YSM 的 `CustomFirstPersonArmRenderer`（`translate(±0.25, 1.8, 0)`、`scale(-1, -1, 1)`）；
- TACZ 的枪械摆放链（移植自 fpbench，已与游戏截图逐像素核对过）。

源码行号见插件 `src/first_person.js` 和 `src/tacz.js` 的注释。

## 4. 动作

动画面板里有两个“文件”：

| 文件 | 内容 | 能否编辑 |
|---|---|---|
| **生成动作** | 模型现有的动作：导入器生成的动作，或 `ysm.json` 指定的动画文件 | 只读，改了会自动撤销 |
| **我的动作** | 你自己的动作 | 可以 |

- **复制到我的动作**：右键一个生成动作（或 动画 菜单）→“复制到我的动作”，然后在副本上改。**同名动作在游戏里会替换生成的动作**。
- **新建动作**：用 Blockbench 的“添加动画”按钮，新动作自动归入“我的动作”。新名字会作为新动作加入，比如轮盘动作、额外动作。
- **导入到我的动作…**：读入已有的 Bedrock 动画文件。
- 动作名要用 YSM 认识的名字：
  - 第三人称：`idle`、`walk`、`run`、`sneak`、`swing_hand`、`parallel0`～`parallel7` 等，和普通 YSM 模型一样。
  - 第一人称（`fp_arm`）：`parallel0`～`parallel7` 会一直同时播放；生成的手指握持在 `parallel2`。
- 预览里，Molang 变量 `ysm.has_mainhand`、`ctrl.tac_hold_gun`、`ctrl.tac_grip(...)` 会按第一人称的手持状态设置。其他 YSM 变量在 Blockbench 里都按 0 计算。

## 5. 导出

文件 → 导出 →“导出我的动作 (YSM)”（动画 菜单里也有）。两个标签页一起导出：

- 第三人称 → `<模型文件夹>/animations/main.animation.json`
- 第一人称 → `<模型文件夹>/animations/fp_arm.animation.json`

细节：

- **只写“我的动作”**，格式是 Bedrock 动画，旋转和位移的正负号和 YSM 读取的一致。
- 关键帧时间原样保留（Blockbench 平时会把时间对齐到网格，插件导出时不会）。
- 没有“我的动作”的那一组不会生成文件；没有叠加文件的模型在游戏里和以前完全一样。
- 如果 `humanoid.json` 里用 `"animations"` 指定了别的路径，就写到那里。
- 网页版会下载这两个文件，自己放进 `animations/` 文件夹。
- 动画面板里“我的动作”的保存按钮和 Ctrl+S 也走这个导出。

**游戏里生效**：`/ysm model reload`（或重启游戏）。叠加文件会严格编译：写错的 Molang 会报错，报错信息里有文件名、动作名、骨骼和时间，不会悄悄变成 0。

**保存工程**：文件 → 保存项目（.bbmodel）。工程里会记住模型路径和骨架文件，重新打开会自动重建蒙皮预览。网页版或缓存不在时，会提示你重新导出或选择 .ysmrig.json。

## 6. 贴图绘制

1. 在第三人称标签页：图像 →“载入模型贴图（绘制）”。桌面版直接读模型的 VRM，网页版会让你选择 .vrm 文件。
2. 贴图面板按材质分组，列出：
   - 材质用到的每一张 glTF 图片：底色、法线、自发光……；
   - endfield_npr 的渲染贴图：
     - 每个材质的 `prop`、`emission`、`line`、`normal`、`splitNormal`、`outlineMask`、`browMask`、`parallax`、`baseAlpha`；
     - 全局的色带（ramps）、皮肤 LUT、面部 SDF / 遮罩 / 高光、虹膜 Matcap、叠加层。
3. 切到“绘制”模式，用 Blockbench 的画笔、填充等工具在 2D 编辑器里画。
4. 3D 预览：
   - 改**底色**时，模型马上更新：贴图会按导入器的方式重新贴进图集里该材质的位置；
   - 打开 图像 →“预览贴图”后，选中的渲染贴图（法线、属性图、线条……）会作为普通贴图显示在使用它的材质上；
   - 色带、LUT、Matcap、叠加层不按模型 UV 采样，只能在 2D 里看。
5. 图像 →“写回 VRM”：
   - 改过的图片重新编码成 PNG，写回 VRM，其他所有数据逐字节保持不变；
   - 桌面版先把旧文件备份成 `<模型>.vrm.bak`，第一次还会另存 `<模型>.vrm.original.bak`；
   - 网页版会下载新的 .vrm，自己替换原文件（先备份）。
6. 游戏里 `/ysm model reload`。

## 7. 限制

- 预览用普通光照（Lambert），不是游戏里的 endfield_npr 着色。描边外壳、表情 morph 不显示。
- 预览按导出时的像素尺寸显示，不乘第三人称的 `renderScale`（游戏里第三人称会整体缩放，约 0.9）。
- Blockbench 不能执行 YSM 的大部分 Molang 变量（按 0 计算），所以带条件的生成动作在预览里只显示默认分支。
- 生成动作里的 catmullrom 关键帧带 Molang 表达式，Blockbench 的检查器会报警告或错误，不影响使用。
- 第一人称视图：
  - 摆放的是静止状态（没有走路晃动、视角摇晃、切换物品的过渡）；
  - 只考虑主手是右手；
  - 双手模式下，左臂根骨骼（LeftArm）的变换手柄方向可能和画面不一致，但关键帧数值是对的。
- TACZ 参考枪：
  - 是 `static_idle` 第 0 帧的静态姿势，不画配件、弹壳、枪口火焰；
  - 拟合握把表只有内置的 tacz:m4a1；
  - 枪包要每次打开 Blockbench 后重新选择。
- 贴图绘制：
  - 只支持 VRM（GLB）；
  - 预览里的底色是近似合成（缩放、乘底色系数、不透明材质强制不透明），下次导入时导入器会精确重建；
  - 平铺贴图（line、parallax）的预览按 Unity 的平铺参数近似显示；
  - 3D 画笔（直接在模型上画）没有做。
- 桌面版的 Java 导入在 Windows 上没有实测过：本机是 Linux，用 Node 模块模拟测试了同一套代码。
