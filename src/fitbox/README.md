# YSM FitBox：按 YSM 模型外形自动适配碰撞箱和受击判定

Forge 1.20.1（47.x）模组，模组 ID 为 `ysm_fitbox`，依赖 YesSteveModel（`ysm`）。
服务端和客户端都要安装：碰撞箱的移动预测在客户端进行，两端尺寸必须一致。

## 功能概要

| 项目 | 效果 |
|---|---|
| 碰撞箱 | 每个玩家的宽、高和眼高按其 YSM 模型逐姿态拟合。覆盖站立、潜行、游泳、陆地爬行、鞘翅、睡觉、激流，骑乘（坐、骑马、骑猪/炽足兽、坐船），以及战地机动（Battlefield Movement，下称 BFM）的趴下、趴下/起身过渡、两种滑铲和飞扑。 |
| 精确受击 | 每个身体部位一个胶囊体或有向盒，共 15 个：头、胸、腰、左右上臂、前臂、手、大腿、小腿、脚。它们由模型的蒙皮网格拟合，绑在对应骨骼上。 |
| 准星和近战拾取（客户端） | 使用 YSM 当前帧的真实骨骼姿态。射线碰到碰撞箱但没碰到任何部位，就判为没打中，比如瞄准两腿之间。 |
| 服务端判定 | 弹射物（含 TACZ 子弹）、近战校验和爆炸优先使用**玩家自己客户端上报的实时形状**（每 tick 一次，服务端校验后使用）；没有新鲜上报时，用服务端近似形状：当前状态的动画片段 + 身体朝向 + 头部朝向。 |
| 弹射物膨胀 | 默认 0：箭、弩箭、三叉戟、投掷物、TACZ 子弹只在 F3+B 画出的形状内命中。可整体或按实体类型改回原版膨胀值。 |
| TACZ | 软依赖。装了 TACZ 时，子弹对适配玩家只测部位形状；命中 HEAD 部位即 TACZ 爆头（按枪的爆头倍率结算）。持枪站立、瞄准、趴下持枪各有拟合姿态。 |
| BFM | 软依赖。服务端直接读 BFM 的服务端状态；穿 YSM 模型的玩家，碰撞箱宽高以本模组拟合结果为准。趴下和飞扑时 BFM 沿身体方向拉长的包围盒按模型身长计算（需 BFM 1.7.24），模型的头和脚不进墙。 |
| 不适用的玩家 | 没装 YSM、模型被禁用、客户端没装本模组或没有 YSM 通道的玩家，保持原版碰撞箱和原版判定。 |

## 给玩家

- 按 **F3+B** 显示碰撞箱时，额外显示受击形状：
  - 白框：拟合后的碰撞箱（就是你真实的碰撞箱）；
  - 绿色：实时骨骼上的受击形状，也就是准星实际测试的形状；
  - 橙色：服务端近似形状。服务端在收不到你客户端的实时上报时才用它。
- 换模型后，新碰撞箱要等你所在位置放得下才生效，不会把你卡进方块。例如在一格高的通道里换成更高的模型，会先保留旧碰撞箱，走出通道后再切换。
- 站起来、从爬行恢复、下坐骑也一样：放不下更高的碰撞箱时，原版姿态逻辑会让你保持潜行或爬行。
- 客户端配置 `config/ysm_fitbox-client.toml`：
  - `showLiveShapes`、`showServerShapes`：F3+B 下显示哪一组形状；
  - `logPicks`：准星对适配玩家的判定结果变化时写入客户端日志，排查问题用。

## 给服主

### 安装

把 `ysm_fitbox-0.2.2.jar` 放进服务端和客户端的 `mods/`。两端版本必须一致（网络协议版本 2，0.1.0 客户端进不了 0.2.0 服务端）。
没装本模组的客户端也能进服，但这些玩家自己保持原版碰撞箱，服务端对他们用近似形状。
TACZ、BFM 都是可选的，装不装都能运行。

### 配置：`<世界>/serverconfig/ysm_fitbox-server.toml`

修改后自动重载，并同步到所有客户端。

| 键 | 默认 | 说明 |
|---|---|---|
| `general.enabled` | true | 总开关。关闭后所有人恢复原版。 |
| `general.fitCollision` | true | 是否拟合碰撞箱（宽、高、眼高）。 |
| `general.preciseHits` | true | 准星、弹射物和近战是否使用部位形状。关闭后只用拟合后的碰撞箱。 |
| `general.validateMelee` | true | 服务端用攻击者视线重新检测服务端形状，没打中就取消这次攻击。 |
| `general.meleeTolerance` | 0.6 | 近战校验时形状向外放大的格数，用来吸收延迟，以及服务端不跑动画造成的误差。 |
| `general.preciseExplosions` | true | 爆炸的暴露度在部位形状的采样点上计算。 |
| `general.logHits` | false | 弹射物接近或命中、近战校验的结果写入服务端日志，调试用。 |
| `limits.minWidth` / `maxWidth` | 0.4 / 0.98 | 碰撞箱宽度上下限，所有姿态都适用。上限请保持在 1 以下：宽度达到 1 格就会与 1 格宽通道两侧的墙重叠；骑乘时，判定窒息的方块是以眼睛为中心、边长为 0.8 × 宽度的正方形，宽度过大时它会超出矿车、猪这类窄坐骑的范围。 |
| `limits.minHeight` / `maxHeight` | 1.0 / 2.6 | 直立姿态（站、潜行、坐、骑）的高度上下限。 |
| `limits.minLyingHeight` / `maxLyingHeight` | 0.35 / 0.95 | 躺姿（游泳、陆地爬行和 BFM 趴下、趴下/起身过渡、飞扑、鞘翅、睡觉、激流）的高度上下限。上限小于 1，趴着能钻 1 格高的空隙。两种滑铲用 `minLyingHeight` ～ `maxHeight`。 |
| `projectiles.projectileInflate` | 0.0 | 弹射物命中时部位形状向外放大的格数。0 = 正好是 F3+B 画出的形状；-1 = 用弹射物自己的原版值（箭 0.3）。 |
| `projectiles.projectileInflateOverrides` | 空 | 按实体类型覆盖，格式 `"命名空间:路径=值"`，例如 `"minecraft:trident=0.1"`、`"tacz:bullet=0"`，值的含义同上。 |
| `projectiles.taczPrecise` | true | TACZ 子弹对适配玩家只测部位形状，HEAD = 爆头。关闭后 TACZ 用它自己的碰撞箱和爆头判定。 |
| `live.enabled` | true | 接受客户端上报的实时形状。关闭后服务端只用近似形状。 |
| `live.maxAgeTicks` | 10 | 上报超过这么多 tick 未更新即视为过期，改用近似形状。 |
| `live.sizeTolerance` | 0.2 | 上报形状的尺寸（半径、胶囊长度、盒子半边长）与近似形状的允许相对偏差，超出部分夹到边界。防止缩小头部躲爆头。 |
| `live.headTolerance` / `trunkTolerance` / `limbTolerance` | 0.4 / 0.5 / 1.2 | 上报形状中心与近似形状中心的允许距离（头、躯干、四肢），超出则该部位换成近似形状。 |
| `live.regionMargin` | 0.75 | 上报形状中心必须落在"当前碰撞箱 ∪ 所报状态的拟合碰撞箱 ∪ 近似形状范围"外扩此值之内，否则换成近似形状。 |
| `live.maxReplacedShapes` | 4 | 一次上报里需要替换的部位超过此数，整份上报作废。 |

**公平性**：模型站立高度低于 `minHeight` 时，碰撞箱按下限放大，受击形状和眼高也绕脚底按同一比例放大。
因此超小模型在 PvP 里不会难以命中。

### 指令（权限等级 2）

- `/fitbox info <玩家>`：显示该玩家当前所处状态、当前碰撞箱和眼睛相对位置（含沿身体方向的前移量），以及各状态的碰撞箱（限幅后和限幅前的尺寸）、眼高和所用动画片段。
- `/fitbox mannequin <模型> <x y z> <朝向>`：放一个穿指定模型的假人。
  - 模型 ID 写法和 `/ysm model set` 一样，例如 `sample`、`"local:custom/vrm1_sample"`。
  - 用途是从外面观察拟合效果，以及测试命中。
  - 假人不受伤害，不随世界保存，服务器关闭时自动移除。
- `/fitbox mannequin remove`：移除假人。

服务端首次拟合某个模型时，会在日志里写一段 `Fitted YSM model <hash>` 报告，包含部位、采样数、各姿态尺寸和所用动画片段。

## 工作原理

### 数据来源

| 端 | 来源 |
|---|---|
| 服务端 | YSM 服务端自己执行人形导入（VRM/PMX 转成 YSM 模型），并把转换结果缓存在 `ysm/cache`。<br>玩家的选择记录在 `ModelInfoCapability` 的模型哈希里；没有选择时，用 YSM 默认模型。<br>本模组从 YSM 目录取出该模型玩家目标的 `GeoModelProto`（骨骼、蒙皮网格、权重，或经典模型的方块）和主动画文件，在后台线程拟合一次，按模型哈希缓存。<br>每个 tick 比对每个玩家的模型哈希、禁用状态和通道，变化时重新取用缓存或拟合。 |
| 客户端 | 客户端不保留网格数据，所以拟合结果由服务端通过 `ysm_fitbox:main` 频道下发。下发时机：玩家自己的形状生效时，以及别人开始看到该玩家时。<br>客户端用同一份数据和同一组限幅计算碰撞箱，结果与服务端逐位一致。 |

### 拟合

- **采样**：
  - 蒙皮网格取每个顶点，权重为周围三角形面积的三分之一；
  - 经典方块模型在每个面上取 4×4 个采样点。
- **排除松散部件**：主权重骨骼是弹簧骨（VRM/PMX 的头发、裙摆物理），或名字含 hair/skirt/ribbon/cape/tail 等的骨骼，连同其子骨骼一起排除。头发和裙摆不会撑大碰撞箱，也不算受击部位。
- **摆姿态**：每个状态先用模型自己的同名动画片段，没有就用 YSM 内置默认片段（YSM 本身也是按名借用默认片段）。片段按状态取 t=0、片段中点或末帧（关键帧之间线性插值），再用线性混合蒙皮摆出姿态。片段在拟合时从模型里读取，所以导入器以后改了 bfm:*、tac:* 片段，形状会自动跟上。
  - TACZ 持枪状态把 `tac:<姿势>:<枪型>` 片段叠在身体片段上，片段里有的骨骼以它为准。
  - 编译后的 Molang 关键帧，用 YSM 自带的解码器读出语法树，再按"空手、静止"求值。例如导入器生成的 `ysm.has_mainhand ? ... : (-38)` 会得到 -38。
  - 潜行额外下移 1/8 格，这是原版 PlayerRenderer 的渲染偏移，YSM 也画在这个位置。
  - 睡觉额外绕 Z 轴转 90°、绕 Y 轴转 270°，与原版睡姿旋转一致。
- **碰撞箱尺寸**（均为面积加权分位数）：
  - 高度：身体采样 y 坐标的 99.5% 分位；
  - 直立姿态的宽度：`max(|x|,|z|)` 的 98.5% 分位 × 2；
  - 躺姿的宽度：沿身体横截面方向计算（与原版 0.6 方形游泳箱的思路相同），不取身长；
  - 手臂不计入宽度（原版 0.6 宽也不含手臂），但计入高度和受击形状。
- **眼高**：取 LeftEye/RightEye 骨骼在该姿态下的位置；没有眼骨时，取头部骨骼往上 30% 处。
- **受击形状**：
  - 四肢和头用胶囊体。四肢的轴线是本骨骼枢轴到下一段枢轴的连线（肩→肘、肘→腕、髋→膝、膝→踝）。半径取 90% 分位，两端各裁掉 1%。
  - 胸、腰用模型轴对齐的盒子。
  - 手、脚：形状明显细长时用主成分方向的盒子，否则用轴对齐的盒子。

### 状态对照表

| 状态 | 进入条件（服务端 / 客户端） | 片段（取样位置） | 碰撞箱 |
|---|---|---|---|
| STANDING | 原版站立 | `idle`（起点） | 拟合，直立限幅 |
| CROUCHING | 原版潜行 | `sneaking`（起点，下移 1/8 格） | 拟合，直立限幅 |
| SWIMMING | 原版游泳姿态且在水中 | `swim` | 拟合，躺姿限幅 |
| CRAWLING | 原版游泳姿态但不在水中（陆地爬行）；BFM 趴下（`ProneManager.isActive`，阶段 2） | `climbing`（YSM 爬行静止片段） | 拟合，躺姿限幅（≤0.95） |
| PRONE_ENTER / PRONE_EXIT | BFM 趴下阶段 1 / 3 | `bfm:prone_enter` / `bfm:prone_exit`（中点） | 拟合，躺姿限幅 |
| SLIDE | BFM 滑铲，配置 `SLIDE_CROUCH_STYLE=false`（战地 5 / CoD 后仰滑铲） | `bfm:slide` | 拟合，滑铲限幅 |
| SLIDE_CROUCH | BFM 滑铲，`SLIDE_CROUCH_STYLE=true`（战地 1 蹲姿滑铲） | `bfm:slide_crouch` | 拟合，滑铲限幅 |
| DIVE | BFM 飞扑（`DiveServer.isDiving`） | `bfm:dive`（末帧） | 拟合，躺姿限幅 |
| GUN_HOLD / GUN_AIM（rifle / pistol） | 主手持 TACZ 枪；瞄准进度 > 0 时为 AIM；枪型 pistol 用 pistol，其他用 rifle | `idle` + `tac:hold:<型>` / `tac:aim:<型>` | 同 STANDING |
| GUN_PRONE（rifle / pistol） | CRAWLING 时主手持 TACZ 枪 | `climbing` + `tac:climbing:<型>` | 同 CRAWLING |
| 鞘翅、睡觉、激流、骑乘各状态 | 原版 | `elytra_fly`、`sleep`、`riptide`、`sit`/`ride`/`ride_pig`/`boat` | 拟合 |

BFM 状态的读取：服务端用 BFM 自己的服务端状态（`ProneManager`、`SlideServer`、`DiveServer`，趴下阶段读 `ProneManager` 的内部表，全部反射读取，不硬依赖）；
只有服务端反射失败时，才采用客户端随实时形状一起上报的状态（只接受 BFM 能产生的状态，状态切换至少间隔 2 tick，且照常校验形状）。
客户端用 BFM 的客户端接口（`ProneClient`、`SlideClient`、`DiveClient`）。趴下时模型朝向用 BFM 的 `ProneGeometry.bodyYaw`，与 YSM 的做法相同。

### BFM 碰撞箱接管

BFM 不改实体尺寸，而是直接改写玩家的包围盒：
- `Entity.makeBoundingBox`（RETURN）和 `Entity.setBoundingBox`（HEAD）被它改写；
- 趴下时，沿身体方向把包围盒拉长（BFM 1.7.23 按 Steve 前后各 0.72 格）；
- 滑铲时，高度压到 1.18（后仰滑铲）或 1.38（蹲姿滑铲）；
- 飞扑时，高度压到 0.88，并像趴下一样沿身体方向拉长。

BFM 的这些包围盒都以 `Player.getDimensions` 为底，而它由本模组的 mixin 给出拟合尺寸，所以底面宽度本来就是拟合宽度。
另外在 Forge `EntityEvent.Size` 上以最低优先级（并接收已取消事件）兜底，覆盖用该事件改尺寸的其他模组。

**沿身体方向的长度（0.2.2）**：BFM 1.7.24 增加了 `ProneGeometry.reach(Player, 方向)`，问"趴着的身体从实体位置往前、往后、往两侧各伸出多远"，默认答 Steve 的 0.72/0.72/0.29。
本模组（`BfmReachMixin`）对穿 YSM 模型的玩家，按趴姿（持 TACZ 枪时用持枪趴姿）或飞扑末帧的拟合形状回答：
- 往前到头部最前端，往后到脚，手臂不算，与底面宽度的规则相同；
- 往前至少到眼点再加原版窒息判定方块的半宽（0.4 × 碰撞箱宽，`Entity.isInWall` 以 `getEyePosition` 为中心），脸贴墙时眼睛不用后退，也不会窒息；
- 两侧为拟合宽度的一半。

the sample model：往前 0.887（头部最前端 0.821，眼点 0.718），往后 1.116。BFM 只在包围盒放得下时才拉长，放不下时保留上一刻的或退回底面，所以 1 格宽的通道里照样能转身。

对穿 YSM 模型的玩家，本模组在 `Entity.setBoundingBox` 的末尾（TAIL）只修正高度：写入的包围盒比当前状态的拟合高度高时，压到拟合高度（例如滑铲、飞扑），底面保持 BFM 写入的样子。没有 YSM 模型的玩家不受影响，BFM 照常工作。

0.2.1 及以前在这一步把底面改回拟合宽度的正方形，BFM 的拉长部分因此被丢掉：the sample model 趴着时身体前后各伸出碰撞箱约 0.9 格，爬向墙时头先进墙，眼点随之被防穿墙逻辑拉回到腰部。

**为什么以前趴下、滑铲时形状会离开模型**：
- 服务端近似形状原先只认原版姿态。陆地爬行和 BFM 趴下都被当成"游泳"，用的是 `swim` 片段（身体前移 21 像素、前倾 72.5°），而 YSM 实际播放的是 `climbing`。
- 滑铲和飞扑原先被当作站立，TACZ 持枪也没算进去。
- 客户端上报（新增）原先按原版身体朝向摆放，而 YSM 趴下时用的是 BFM 的趴下朝向。

现在这三处都已按上表的状态处理。
- BFM 的根变换（`PronePoseRenderer`/`DivePoseRenderer.applyRoot`）挂在原版 `PlayerRenderer.setupRotations` 上，而 YSM 用自己的渲染器替换了玩家渲染，所以它不作用于 YSM 模型。
- YSM 模型的趴下、飞扑全靠 YSM 自己的片段和朝向。绿色实时形状来自 YSM 绘制时的同一条变换链，与网格一致。（[推断] 尚未用 1.20.1 版 BFM 在游戏里对照。）

### 趴下时眼睛在头部（0.2.1，0.2.2 修订）

**问题**：原版爬行和 BFM 趴下时，玩家的真实眼位在身体中心（腰部），而 YSM 模型的头在前方大约一格处。BFM 为方块人按 Steve 的尺寸把眼睛前移 0.6 格、高 0.4 格，但这套数字不是 YSM 模型的；原版爬行则完全没有前移。

**做法**：穿 YSM 模型的玩家处于以下状态时，眼睛放在模型实际的头部：
- 陆地爬行、BFM 趴下（含趴下/起身过渡）、两种滑铲、飞扑。
- 眼点取该状态拟合片段里 LeftEye/RightEye 骨骼的中点；没有眼骨时，取头部骨骼往上一段。
- 趴着手持 TACZ 枪时，YSM 叠加 `tac:climbing:rifle|pistol`，头部前移约 0.3 格，眼点改用持枪趴姿（0.2.2）。
- 方向按模型实际朝向：BFM 的 `ProneGeometry.bodyYaw`；没有 BFM 时用身体朝向，与 YSM 一致。
- 过渡阶段按 BFM 自己的进度（`StanceTransition.amount`，取自 `ProneManager.eyeHeight`/`ProneClient.eyeHeight`），在站立眼点与爬行眼点之间插值；飞扑的 0.3 秒前扑在客户端按 BFM 的 `DiveClient.extension` 从站立眼点插值到飞扑眼点（0.2.2）。
- 眼点离身体中心不足 0.2 格的不做水平移动。
- 片段按模型自带优先、内置默认补位读取：导入模型自带 `climbing`/`climb` 时用自带的，没有时用 YSM 内置的。

**平滑（0.2.2）**：眼点和实体位置一样按 tick 推进、按帧插值。
- 每个玩家 tick 结束时（两端都做），眼点向该状态的目标点走剩余距离的一半（4 tick 走完 15/16）；
- 每帧取上一 tick 与本 tick 眼点之间、按该帧的 partial tick 插值的点，再转到插值后的朝向、放到插值后的位置；
- 离开这些状态时，先平滑回到原版眼高，到位后才交还原版。
- 0.2.1 在状态切换时直接跳到新眼点：飞扑开始时相机一帧下降 1.3 格、前移 0.9 格；落地转趴下时先上跳再按 20 Hz 台阶下降（BFM 的进度只在 tick 上取值）。离线模拟（`FitTests`，60 fps）中，飞扑→趴下全程的最大单帧位移从 1.593 格降到 0.128 格。

**挂钩位置**：在源头改，所有使用方自动一致。
- `Entity.getEyeHeight`/`getEyeY`/`getEyePosition()`/`getEyePosition(float)`（RETURN，优先级 900）。依赖它们的有：
  - 客户端：准星与方块拾取射线；
  - 服务端：近战与方块交互距离；
  - 窒息检测；
  - 原版箭、投掷物的出发高度。
- 客户端相机：原版相机不读 `getEyePosition`，因此在 `Camera.setup` 放置位置之后、第三人称后拉之前，改到同一个眼点。
- 弹射物水平出发点：原版箭/弩箭/三叉戟（`AbstractArrow`）和投掷物（`ThrowableProjectile`）以射手 `(x, eyeY-0.1, z)` 出发，改为眼点下 0.1。
- TACZ 子弹出发点改为眼点（与 BFM 自己的 TACZ 修正相同）。

**防穿墙**：眼睛从身体中心、在眼高处向头部点移动，只走到路径无方块阻挡为止（二分查找，并与方块面保留 0.08 格间距），绝不会进入方块。
- 判断依据是"更远的点是否仍然畅通"，因此向前移动时不会出现 BFM 1.7.23 修过的那种方向反转、眼睛被拉回的问题。
- 被挡时立即后退；挡住的东西让开后（例如爬过门框、转开身），每 tick 最多放出 0.06 格，与 BFM 自己的头部恢复速度相同，不再一帧弹回原位（0.2.2）。
- 游戏内实测（0.2.1）：眼前 0.5 格处放一块木板，眼点从 0.600 退到 0.420，第一人称画面贴着木板，准星选中的正是这块木板。

**与 BFM 的配合**：对穿 YSM 模型的玩家，BFM 的显式眼高（`ActionEyeHeight.target`）和趴下头部点（`ProneGeometry.headPosition`）被改成返回本模组的值。
离线 mixin 检查（`tools/mixincheck`，用 Forge 1.20.1 所带的 Mixin 0.8.5 把两个模组的 mixin 配置真正应用到生产环境的类上）确认：
- 本模组的 BFM mixin 全部作用在 1.20.1 移植版上；
- 在 `getEyePosition`/`getEyeHeight`/`getEyeY` 里，本模组的回调排在 BFM 之前，返回值一旦设定就直接返回，BFM 的眼位修正不再执行；
- `Camera.setup` 里 BFM 的相机回调最后执行，但它写入的是 `getEyePosition(partial)`，也就是本模组的眼点。
没有 YSM 模型的玩家不受影响：BFM 和原版行为都不变。

### 哪条判定路径用哪种形状

| 路径 | 挂钩位置 | 使用的形状 |
|---|---|---|
| 准星和近战拾取（客户端） | `ProjectileUtil.getEntityHitResult(Entity,…)`，即 `m_37287_`，由 `GameRenderer.pick` 调用 | 实时形状。YSM 每次绘制该玩家时，在 `RenderModelEvent` 里读取 `BonePoseView.getPose(骨骼)`，乘以本次绘制的模型到世界矩阵，就得到实时形状。下一帧拾取时，把它放到该帧的插值位置上。<br>该玩家最近两帧没被画出时（视锥外、隐身），改用服务端近似形状。 |
| 弹射物：箭、弩箭、三叉戟、投掷物、烟花，以及走 ProjectileUtil 的模组弹射物 | `ProjectileUtil.getEntityHitResult(Level,…,float)`，即 `m_150175_` | 服务端：目标自己的实时上报形状（新鲜时），否则近似形状；按 `projectileInflate`（默认 0）放大。客户端的弹射物预测用近似形状。 |
| TACZ 子弹（服务端） | `com.tacz.guns.util.EntityUtil.getHitResult`，在它取 `HitboxHelper.getFixedBoundingBox` 处注入（TACZ 1.1.8 与 1.2.0 相同） | 同上，用本 tick 子弹线段测试；首个命中部位为 HEAD 即爆头。TACZ 的伤害忽略名单和队伍友伤检查照常先执行。非适配实体走 TACZ 原逻辑。 |
| 服务端近战校验 | `AttackEntityEvent`（服务端） | 实时上报形状或近似形状，放大 `meleeTolerance`，用攻击者在服务端记录的视线检测，射程为 reach + tolerance。 |
| 爆炸暴露度 | `Explosion.getSeenPercent`，即 `m_46064_` | 实时上报形状或近似形状的采样点：每个胶囊体取两端和中点，每个盒子取中心和 8 个内缩 30% 的角点。 |
| 其他（横扫、压力板、实体推挤、摔落等） | 原版 | 拟合后的碰撞箱。 |

**实时上报**：装了本模组的客户端每个客户端 tick 发送一次自己玩家的 15 个部位形状，约 330 字节。
- 坐标相对玩家位置、世界朝向，按 1/1024 格量化；同一份上报带上 BFM 状态和身体朝向。
- 形状来自 YSM 的每实体渲染状态：每帧都会提取，第一人称下也有。根变换按 YSM 渲染器的方式重建：潜行下移、睡姿、BFM 趴下朝向、渲染缩放。
- 服务端每 tick 最多处理 2 份上报，用所报状态的近似形状校验（见配置 `live.*`）：尺寸超差就夹紧，位置超差就换成近似形状，替换过多就整份作废。
- 作废、过期（超过 `maxAgeTicks`）或客户端没装本模组时，改用近似形状。

**服务端近似形状**：当前状态的片段（按上表取样）乘以身体朝向；头部形状再按头部偏航和俯仰，绕头部枢轴转动。
睡觉时按床的方向和 YSM 的床位偏移摆放。近似形状不含走路摆臂、挥手、换弹等动画。

**其他模组的弹射物**：走 `ProjectileUtil` 的模组弹射物自动被覆盖。下列模组有各自的射线检测，不经过本模组（[推断]，按这些模组公开的源码结构判断，未逐一验证）：
- SuperbWarfare（`ProjectileEntity` 自带路径检测，结构与 TACZ 类似）；
- MrCrayfish's Gun Mod；
- Point Blank / Vic's Point Blank（自有 hitscan）；
- Better Combat、Epic Fight（近战用自己的碰撞体，客户端拾取不走 `GameRenderer.pick`）。

## 已知限制

- 碰撞箱只能是轴对齐的正方形底面，所以：
  - 躺姿（游泳、鞘翅、睡觉）的碰撞箱只覆盖身体横截面，不覆盖身长。命中判定仍然覆盖全身，因为所有路径都搜索碰撞箱外扩 1 格的范围。
  - 斜着站时，肩膀可能比碰撞箱多出几厘米，原版也是这样。
- 实时上报有一个网络往返的延迟：服务端用的是该玩家客户端约半个 ping 以前的姿态，位置用服务端当前位置。
- TACZ 的延迟补偿（按射手 ping 回退目标碰撞箱）不作用于部位形状。
- 上报可被作弊客户端伪造，但只能在 `live.*` 的容差内移动部位，不能缩小部位。
- 没装本模组的客户端、无新鲜上报时，服务端用近似形状：它不含行走、挥手、换弹等动画，只有当前状态片段在固定取样点的姿态，加上头部朝向。近战校验靠 `meleeTolerance` 补偿这部分误差。
- Molang 求值假定空手、静止，也就是变量、查询和 YSM 函数都按 0 计算。TACZ 枪型只拟合 rifle 和 pistol 两种，其他枪型按 rifle 处理。
- BFM 部分全部用反射和 mixin 读取，对不上时：
  - 服务端读不到时，退回客户端上报的状态；
  - 客户端读不到时，退回原版姿态；
  - BFM 1.7.23 没有 `ProneGeometry.reach`：`BfmReachMixin` 不生效（require = 0），趴下包围盒按 Steve 前后各 0.72 格拉长。
  对 1.20.1 移植版（1.7.23、1.7.24）已用 `tools/mixincheck` 离线核对过：反射读取的类和方法都在，所有 BFM mixin 都作用到了目标方法上。
- 平滑后的眼点在状态切换后约 0.2 秒内落后于目标（服务端同样平滑，两端一致）；这段时间里 TACZ 子弹从平滑中的眼点出发。
- YSM 的 `climbing`（静止）和 `climb`（爬动）眼高差约 6 cm，眼点按静止片段取；趴着朝侧面看时 YSM 会把上身和头一起转过去，眼点仍在身体轴线上（BFM 对方块人也是这样处理）。
- 眼点的防穿墙间距是 0.08 格，小于原版窒息判定方块的半宽（约 0.17 格）：正前方由 BFM 包围盒保证不会贴墙，但侧前方被方块角挡住、眼点后退时，`isInWall` 仍可能判定为在墙内（0.2.1 起就是这样，未改）。
- 松散部件只按弹簧骨和名字识别。没有弹簧数据、名字又不规范的头发或披风，会被当作身体的一部分。
- 骨骼名不符合 YSM 人形骨架的模型（Head、UpBody、LeftArm、LeftLeg 等，部位少于 8 个），退化为一个整体盒子。
- 没有网格也没有方块的模型，以及读取失败的模型，退回原版碰撞箱，大约 10 秒后重试。
- `/fitbox mannequin` 是测试工具：假人不 tick，不受伤，只在当前维度可见。
- 模组要求两端都安装。服务端会把没有本模组频道的客户端的玩家保持为原版。

## 构建

```bash
~/ysm/fitbox/build.sh        # 生成 build/ysm_fitbox-<版本>.jar
```

构建方式与 endfield_npr 相同：
1. 用 javac 编译，编译依赖为 `~/ysm/npr/mcdev` 下的 Mojang 命名 MC/Forge jar 和 YSM jar（需先运行一次 `~/ysm/npr/mod/tools/remap-mc.sh`）；
2. 用 ForgeAutoRenamingTool 和 `moj2srg.tsrg` 改成 SRG 名；
3. Mixin 目标直接写 SRG 名（`remap = false`），所以不需要 refmap。
