# 1.7.24 修复说明

适用版本：**1.20.1 Forge 移植版**（1.21.1 NeoForge 版未同步）。

- 包：`build/libs/battlefield-movement-1.7.24-forge-1.20.1.jar`
- 网络协议不变（`8-forge1.20.1`），但趴下朝向和包围盒两端各算一份，**服务端和客户端都要换成 1.7.24**。
- 配合 YSM FitBox 0.2.2 使用时，YSM 模型趴下的包围盒按模型身长计算；不装 fitbox 时行为与 1.7.23 相同，只有第一项不同。

## 趴着往前爬时身体斜着平移

### 症状

穿 YSM 模型趴下，往前爬时身体和头都歪着，看起来像在侧向平移，而不是朝身体方向爬。

### 原因

- 趴下的身体朝向（`ProneGeometry.bodyYaw`）有 35° 的自由视角区：视线偏离身体不超过 35° 时身体不转，超过后每 tick 转超出部分的 35%，最多 9°。爬行时也是这样。
- 爬行方向跟着视线走。边爬边用鼠标转向时，身体朝向最终停在视线后方 35° 处，所以身体与前进方向一直差 35°。
- 原版方块人：BFM 自己的趴姿渲染器用身体朝向放身体，头按"视线 − 身体朝向"转，所以头仍朝前进方向，腿用侧向步态。
- YSM 模型：YSM 用同一个身体朝向放模型（`BfmCompat.proneYaw`），但 `climbing`/`climb` 片段里上身和头的转角取自 `ysm.head_yaw`，即"视线 − **原版身体朝向**"。趴下速度约 0.04 格/tick，低于原版身体跟随移动方向的门槛（0.05），原版身体朝向只在落后视线 50° 以后才跟上，与 BFM 的朝向不是一回事。所以 YSM 模型的身体斜着，头也不朝前进方向。

### 修改

- `ProneGeometry.turn(身体, 视线, 是否在爬)`：自由视角区只在趴着不动时有效。爬行时没有自由视角区，身体朝视线转，仍是超出部分的 35%、每 tick 最多 9°。两端各自用位置变化判断是否在爬：最近 3 个 tick 里有一个 tick 水平移动超过 0.01 格就算在爬。多留两个 tick，是因为服务端只在收到移动包时才看到位置变化，有的服务端 tick 收不到包。
- 客户端每 tick 结束时，把趴下玩家的原版身体朝向（`yBodyRot`/`yBodyRotO`）设成 BFM 的身体朝向。按原版身体朝向计算头部转角的渲染器（YSM）因此和 BFM 自己的趴姿渲染器一样，按"视线 − 身体朝向"转头。

### 验证

`tools/ProneFacingSim.java`（不进游戏，直接调用编译出来的 `ProneGeometry`），场景为：趴下后往前爬，以每 tick 3° 向右转 90°，然后继续直爬。

| | 1.7.23 | 1.7.24 |
|---|---|---|
| 转完 20 tick 后身体与前进方向的夹角 | 35.0° | 0.0° |
| 同时 YSM 头部与视线的夹角 | 15.0° | 0.0° |
| 边转边爬时身体落后视线 | 40.6° | 5.6° |

不动时 30° 的偏头仍是自由视角，身体不转；不动时偏头 80°，身体转到视线后方 35°（45°）停下；爬行时 30° 的偏差 9 tick 内收敛到 1° 以内。

```bash
./build.sh
DEV=~/ysm/npr/mcdev; CP="build/sim:build/classes:$DEV/client-moj.jar:$(ls $DEV/libs/*.jar | tr '\n' ':')"
javac -cp "$CP" -d build/sim tools/ProneFacingSim.java && java -cp "$CP" ProneFacingSim   # 11 passed, 0 failed
```

## 趴下、飞扑包围盒按身体长度拉长

### 症状

穿 YSM 模型趴下时，模型的头和脚能伸进墙里；爬到墙前时第一人称眼点退到腰部。

### 原因

- BFM 沿身体方向把包围盒拉长到前后各 0.72 格，这是 Steve 的长度。
- the sample model 趴着时，头部最前端在实体位置前方 0.82 格，脚在后方 1.12 格。
- fitbox 0.2.1 又在 `setBoundingBox` 末尾把底面改回拟合宽度的正方形（0.42 格），拉长部分完全丢失。

### 修改

- 新增 `ProneGeometry.reach(Player, AHEAD|BEHIND|SIDE)`：趴着的身体从实体位置往前、往后、往两侧各伸出多远。默认值为 Steve 的 0.72/0.72/0.29，其他模组可以用 mixin 回答，fitbox 0.2.2 回答 YSM 模型的身长。
- `ProneGeometry.envelope(Player, …)` 按这三个值拉长包围盒；前后不等长时，包围盒相对实体位置不对称。
- 前后等长时，计算结果与 1.7.23 逐位相同（模拟器检查了 360 个朝向 × 2 个进度 × 2 个宽度）。
- 选包围盒时的"保留上一刻包围盒"逻辑（防止贴墙时来回伸缩）对不对称的包围盒按偏移量平移到新位置，并逐边比较，而不是只比尺寸。
- 飞扑的拉长也改用 `envelope(Player, …)`。

### 验证

`tools/ProneFacingSim.java` 中的包围盒检查：朝南时 maxZ = +0.85（头）、minZ = −1.12（脚）；朝西时对应 x 方向；半程按一半拉长；45° 时为身体矩形的外接框，并按较长的一端封顶。

**未在游戏内验证。**
